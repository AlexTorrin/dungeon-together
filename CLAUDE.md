# CLAUDE.md

Пошаговый 2D dungeon crawler в духе Pixel Dungeon с кооперативом на 1–4 игроков по сети.
Автор — опытный веб/Android-разработчик, но новичок в геймдеве: объясняй игровые паттерны, когда вводишь их впервые.

## Стек

- **Язык:** TypeScript (strict) везде
- **Монорепо:** pnpm workspaces
- **Клиент:** Phaser 3 + Vite
- **Сервер:** Node.js + Colyseus
- **Рогалик-утилиты:** rot.js (генерация карт, FOV, pathfinding)
- **Тесты:** Vitest
- **Линт/формат:** ESLint + Prettier

## Структура

```
packages/
  shared/   # вся игровая логика: состояние, правила, команды. Без зависимостей от Phaser/Colyseus/DOM
  server/   # Colyseus-комнаты: принимает команды, вызывает shared, рассылает состояние
  client/   # Phaser: рендер, ввод, UI, анимации. Никакой игровой логики
assets/     # спрайты, тайлсеты (2D Pixel Dungeon Asset Pack v2.0), отдаются клиенту как статика; custom/ — свои
docs/       # architecture.md — как всё устроено; assets.md — что лежит в assets/ и что где используется
deploy/     # ubuntu.sh — установка/обновление на сервере Ubuntu (systemd + nginx, сервер за `/server/`)
tools/sprites/  # скрипты, рисующие свои спрайты в assets/custom/ (ASCII-сетка → PNG)
.claude/skills/run-game/  # запуск игры и скриншоты в headless-браузере для проверки изменений
.claude/{agents,commands,rules/ecc,skills}/  # выборка из affaan-m/everything-claude-code @76aaa77, без хуков
```

Прежде чем менять код, загляни в `docs/architecture.md` — там описаны поток данных,
модель ходов, сцены и грабли, на которые уже наступали.

## Команды

```bash
pnpm install
pnpm dev            # клиент (http://localhost:5173) и игровой сервер (:2567)
pnpm dev:client
pnpm dev:server
pnpm test           # тесты всех пакетов
pnpm typecheck
pnpm lint
pnpm format         # prettier --write
```

Чтобы проверить изменение в реальной игре (а не только тестами), используй скил `run-game`.

После любых изменений запускай `pnpm typecheck` и `pnpm test` и убедись, что они зелёные.

## Архитектура — главные правила

1. **Сервер авторитетен.** Клиент отправляет только _намерения_ (команды), сервер проверяет и применяет их. Клиент никогда сам не меняет игровое состояние.
2. **Поток данных:** `Command → shared.applyCommand(state, command) → новое состояние + события → клиенты`.
3. **`shared` — чистый код.**
   - Функции детерминированы: одинаковые вход и seed → одинаковый результат.
   - Никаких `Math.random()`, `Date.now()`, таймеров, I/O. Случайность только через RNG с seed, хранящийся в состоянии.
   - Никаких импортов из `phaser`, `colyseus`, `node:*`, DOM.
4. **Клиент — тонкий.** Он отображает состояние и проигрывает события (анимации ударов, урон, смерть). Решения о результатах действий принимает только `shared` на сервере.
5. **Режим одиночной игры** использует тот же `shared` локально, без сервера. Код логики не должен знать, сетевая игра или нет.

## Игровая модель

- Мир — сетка тайлов; координаты целочисленные `{ x, y }`.
- Сущности (игроки, монстры, предметы) хранятся в состоянии по `id`, а не ссылками.
- Команды и события — размеченные объединения (discriminated unions) с полем `type`.
- Модель очерёдности ходов: **одновременные ходы** (simultaneous turns) с **2 очками действия**. Каждый игрок отправляет план из 1–2 действий (`submitPlan`) и ждёт; когда выбрали все — ход разрешается по двум фазам (`resolveTurn` → `resolvePhase`), `turn` растёт. Удар бьёт клетку по позициям после шагов своей фазы. План в ходу фиксируется, повторный игнорируется. Монстры не задерживают ход: их ИИ составляет план в момент разрешения.
  - Конфликты движения (`resolveMoves`) детерминированы, без RNG: двое в одну клетку — оба упираются; обмен местами запрещён; шаг в клетку, которую сосед в этот же ход освобождает, разрешён; в стоящего на месте — нельзя.
  - Таймера хода пока нет (AFK-игрок блокирует всех) — если понадобится, он живёт на сервере, а не в `shared`.

## Стиль кода

- Небольшие файлы, одна ответственность.
- Предпочитай функции и простые объекты классам в `shared`. В `client` классы Phaser-сцен — нормально.
- Без `any`. Внешние данные (сообщения от клиентов) валидируй на сервере.
- Константы баланса (HP, урон, шансы) выноси в `shared/src/config/`, не хардкодь в логике.

## Тесты

- Любая новая механика в `shared` сопровождается тестами.
- Тестируй через фиксированный seed и явно собранное начальное состояние.
- Клиент и сетевой слой тестами покрывать не обязательно на старте.

## Как работать со мной

- Перед крупной задачей коротко опиши план (какие файлы, какие типы), потом реализуй.
- Делай изменения маленькими шагами, которые можно запустить и проверить.
- Не добавляй новые зависимости без объяснения, зачем они нужны.
- Не трогай `assets/` и конфиги сборки, если задача не про них.
- Если вводишь игровой паттерн (ECS, state machine, FOV, turn scheduler и т.п.), кратко объясни идею в ответе.
- Если меняешь что-то описанное в `README.md` или `docs/` (механику, управление, структуру, используемые ассеты) — обнови документацию в той же задаче.

2. ✅ Генерация уровня (rot.js), персонаж ходит по сетке — локально
   - ✅ ходьба по сетке (8 направлений), одновременные ходы, меню, редактор комнат (с монстрами и оружием)
   - ✅ генерация уровня: `generateLevel(seed)` — Digger из rot.js, монстры и оружие по комнатам
3. ✅ Поле зрения, туман войны (shadowcasting rot.js, общая память команды; монстры тоже видят только в FOV)
4. ✅ Монстры с простым ИИ, бой: удар по клетке после шагов, ближнее/дальнее оружие, выбор хода с подтверждением
5. ✅ Очки действия: 2 ОД на ход, ход из двух фаз; план из двух действий в клиенте, намерения
   с номерами фаз, проигрывание по фазам; боты — по тем же правилам (удар мечом за 2 ОД — шаг 6)
6. ✅ Оружие и инвентарь: нож, лук, меч (удар за 2 ОД, замах), волшебная палочка (дальность 6);
   руки + рюкзак на 4, подбор в рюкзак, взять в руки / выбросить за 1 ОД; монстры — по тем же правилам
7. ✅ Монеты, ключ, дверь; конец уровня (убить всех или выйти дверью, гибель — потеря несённого);
   три сложности уровня; вынесенная добыча — в `state.escaped`
8. ✅ Хаб в меню (лагерь): выбор сложности, магазин (нож и лук по 2 монеты, продажа за полцены), сундук для добычи,
   инвентарь сохраняется между забегами; первый забег — с пустыми руками
9. Сервер Colyseus

   - ✅ 9b: профиль игрока (монеты, снаряжение, сундук) — на сервере по токену, лагерь и все забеги через сервер
